# Release Notes v0.1.0

**Release Date:** October 10, 2026

## Overview

The first release of DataCatalog, a dependency-free Go model for describing
which entities and fields an application stores and how each one is
classified. It is meant to be consumed by query guards, privacy tooling and
documentation generators, so that one definition answers "what data do we
hold, who may see it, and what rules apply to it".

## Highlights

- Fields have an explicit **visibility** (`public` or `internal`) and two
  independent tags, `pii` and `secret`, so a display name, a logged IP
  address and a password hash are each described accurately.
- `secret` implies `internal`, and visibility is never defaulted: an
  unclassified field is an error, not a public one.
- Validation reports every problem at once, with a rule identifier for each.
- Query guards can ask one question, `AllowedInQuery`, which is
  default-deny and always blocks internal and secret fields.

## Installation

```bash
go get github.com/grokify/datacatalog@v0.1.0
```

## New features

### Model

- `Catalog`, `Entity` and `Field`.
- Entity-level attributes: owner, subject key, privacy scope, hold
  applicability, versioning and a retention note.
- Field-level attributes: type, visibility, `pii`, `secret`, erasure
  strategy (`clear`, `tombstone`, `hash`, `delete_row`, `shred`, `retain`),
  retain reason and export flag.

### Validation

- `Validate` on a catalog or an entity returns every problem.
- Rules: names required and unique, visibility required, `secret` implies
  `internal`, subject key required and known, erasure strategy required for
  personal data in privacy scope, retain reason required.

### Filtering

- `VisibleTo` and `VisibleFields` for audiences.
- `AllowedInQuery(allowPII)` for query guards.

### Interchange

- JSON load and save with stable ordering.
- `Merge`, which errors on conflicting definitions of one entity.
- `RenderMarkdown` for documentation tables.
- An embedded JSON Schema generated from the Go types.
